# 日々の予定

スマートフォン向けの予定アプリ。同じソースから次の2つの版を作ります。

- **単一HTML版**：プロジェクト直下の `index.html`。JavaScript・CSS・アイコンを内包し、外部ファイル・CDN・Webサーバー・インターネット接続を必要としません。ファイルを直接開いて使います。
- **PWA版**：`dist/` に出力し、GitHub Pages で公開します（公開URL：`https://<GitHubユーザー名>.github.io/<リポジトリ名>/`）。ホーム画面にインストールでき、一度開いた後はオフラインでも起動します。

## 使用方法

単一HTML版は `index.html` をブラウザーで開きます。PWA版は公開URLを開き、ブラウザーのメニューから「アプリをインストール」（または「ホーム画面に追加」）を選びます。カレンダーの日付または「予定一覧」から日別画面を開きます。

- 月曜日始まりのカレンダーは時刻登録の有無だけを表示します。カレンダー画面には上部のヘッダーがなく、年・月の右に「予定一覧」「今月」とメニューボタン（≡）が並びます。
- 月はカレンダー部分を左にスワイプすると翌月、右にスワイプすると前月に切り替わります（横に50px以上、横の動きが縦の1.5倍以上のとき。画面の左右の端24pxから始めた操作は除く）。スワイプで切り替えたときは日付を開きません。パソコンでは ← → キーとマウスのドラッグでも切り替えられます。
- 予定一覧は今日を初期位置に、過去・未来の日付・曜日・日付タイトルだけを表示します。スクロールに合わせて表示範囲を入れ替え、日別画面から戻ると日付と行内位置を復元します。今日の行は緑の文字・「今日」ラベル・薄い緑の背景で強調し、日付が変わると自動で切り替えます。
- 日別画面は日付タイトルと右横の＋、時刻・経過時間の一覧、複数行メモの順です。日付タイトルとメモは自動保存します。
- ＋で新規時刻入力カード、一覧の時刻部分で修正カードを開きます。どちらも1行目が時刻・自由入力タイトル・タイトル候補、2行目が決定・キャンセル・翌日チェックです。
- カード外タップ・キャンセル・Escで未保存の下書きを破棄します。保存成功後にカードを閉じます。削除は修正カード内で確認します。背景操作を抑止し、閉じた後は元のスクロール位置へ戻します。
- 表示タイトルは自由入力と選択した候補名を区切りなしで連結します。片方だけでも登録できます。
- 時刻は当日00:00からの経過分で自動整列し、翌日指定に1440分を加算します。同じ日付内の同一絶対時刻は登録できません。
- 隣接する時刻の間に経過時間行を生成します。経過時間タイトルは行をタップして自由入力し、自動保存します。
- メニューからタイトル候補を追加・改名・削除・タッチで並べ替えできます。削除した候補名は既存の予定に残ります。
- 日別画面のメニューにある「AI確認用コピー」は、日付・曜日・時刻・予定タイトル・区間タイトル・経過時間と、固定のAI確認依頼文をコピーします。日付タイトル・メモ・内部IDは含めず、予定データも変更しません。自動コピーできない環境では全文を選択できる画面を表示します。AIへの通信や自動的なサイト起動は行いません。
- データ管理からJSONをエクスポート・インポートできます。インポートは確認後に全データを置き換えます。
- 日別画面のメニューにある「この日の予定を全削除」（赤字）は、確認画面で時刻と経過時間タイトルの件数を示してから、その日の時刻をすべて削除します（翌日指定・経過時間タイトルを含む）。日付タイトル・メモ・他の日・タイトル候補・機能追加用メモは残ります。時刻がない日は「削除する予定がありません」と表示します。元に戻す機能はありません。
- メニューの「メモ」に、アプリ全体のメモを自由に書けます（自動保存・エクスポート対象。旧名「機能追加用メモ」、保存データの項目名は `featureMemo` のまま）。

### PWA版の更新とオフライン

- Service Worker が起動に必要なファイル（アプリ本体・manifest・アイコン）をすべて端末にキャッシュします。外部への通信は行いません（CSP の `connect-src 'none'` を維持）。
- 新しい版を公開すると、次にアプリを開いたときにバックグラウンドで取得し、その次の起動から新しい版に切り替わります。古い版のキャッシュは自動で削除します。入力中の画面を勝手に再読み込みすることはありません。
- **単一HTML版とPWA版の保存データは別々です。** 単一HTML版のデータをPWA版で使うときは、単一HTML版でエクスポートし、PWA版でインポートしてください。

## 開発・ビルド・テスト

既存のNode.jsとpnpmを使用します。新しい依存パッケージは不要です。

```powershell
.\project.ps1 install
.\project.ps1 test
.\project.ps1 build
```

`src/standalone.tsx` を起点にReact・TypeScriptとCSSをバンドルし、直下の `index.html`（単一HTML版）と `dist/`（PWA版：`index.html`・`manifest.webmanifest`・`sw.js`・アイコン）を出力します。`dist/` はGitに含めず、GitHub Actions が公開のたびに作り直します。

ブラウザーテストを実行する場合（先に `build` で `dist/` を作っておく）：

```powershell
.\project.ps1 browser-install
.\project.ps1 e2e
```

Playwrightはネットワークを無効にし、完成したHTMLを `file://` で直接開きます。320px/390pxの表示、タッチ操作、時刻編集、区間変更、バックアップ、ブラウザー再起動後の保存復元を検証します。PWA版は `vite preview` で `dist/` をローカル配信し、manifest・アイコン・Service Worker・オフライン再読み込み・保存・インポート・古いキャッシュの削除を検証します。

PWA用アイコン（`public/icon-*.png`）は `public/icon.svg` から作ります。アイコンを変えたときだけ実行します（テスト用ブラウザーが必要）：

```powershell
.\project.ps1 icons
```

`project.ps1` は依存関係、一時ファイル、キャッシュ、テスト用ブラウザーの出力先をこのプロジェクト内に設定します。`node_modules/`、`.cache/`、`.tools/`、`dist/`、`test-results/`、`*.tsbuildinfo` は開発時に再生成でき、配布不要です。ソース・設定・ロックファイルは保持してください。

### 公開（GitHub Pages）

`main` ブランチへ push すると、`.github/workflows/pages.yml` が単体テスト → ビルド → `dist/` の GitHub Pages への公開を自動で行います。リポジトリの Settings → Pages で、Source を「GitHub Actions」にしておく必要があります。

プレビューは `project.ps1 dev` で単一HTMLを再生成してViteを起動します。ソース修正後のHTML更新は `project.ps1 build` を実行してください。

## ソース構成

- `src/model.ts`：新データ型、時刻・日付、時刻登録、候補管理。
- `src/timeline.ts`：時刻順の仮想行、経過時間の計算・整形、現在時刻表示。
- `src/aiCopy.ts`：読み取り専用のAI確認用テキスト生成、Clipboard APIと互換コピー。
- `src/App.tsx`：カレンダー・日別画面・時刻カードの下書き・候補管理。
- `src/Modal.tsx`：モーダル表示、背景のスクロール抑止・位置復元、可視領域への追従。
- `src/autosave.ts`：500msのデバウンス、逐次保存、離脱時の同期退避と回復。
- `src/storage.ts`：IndexedDB、localStorageフォールバック、安全な全置換。
- `src/backup.ts`、`src/DataManager.tsx`：新形式JSONの検証と入出力。
- `src/SortableList.tsx`：タイトル候補専用のタッチ並べ替え。
- `src/sw.js`：PWA版の Service Worker（ビルド時に版番号とファイル一覧を埋め込む）。
- `scripts/build-single.mjs`：単一HTML版とPWA版（`dist/`）の生成。
- `scripts/build-icons.mjs`：PWA用PNGアイコンの生成。
- `public/icon.svg`：HTMLに埋め込むアイコン素材。`public/icon-192.png`・`icon-512.png`・`icon-maskable-512.png` はPWA用アイコン。
- `.github/workflows/pages.yml`：GitHub Pages への自動公開。
- `src/*.test.*`、`tests/*.spec.ts`：単体テストとブラウザーテスト。

## データ形式

アプリデータは `version: 2`、バックアップは `format: "hibi-timeline-backup"`、`schemaVersion: 1` です。旧データ・旧バックアップの変換や読み込み処理はありません。

各日付は `YYYY-MM-DD` キーで `title`、`memo`、`entries` を持ちます。各時刻は `id`、`time`（HH:MM）、`nextDay`、`freeTitle`、`titleId`（未選択はnull）、`elapsedTitle` を持ちます。選択候補は `titles` 配列の順序を使用し、削除済み候補には `deleted: true` を付けます。

表示順は毎回生成し、保存した配列をソートで書き換えません。結合タイトル、経過分、経過時間行は保存しません。区間タイトルは開始時刻行のIDに付属します。途中への追加時は前半区間に残り、削除時は前半側が維持されます。削除対象の区間タイトルは確認後にのみ削除します。時刻編集で最後の行になった場合もタイトルを保持し、再び区間ができれば表示します。

アプリデータには任意項目 `featureMemo`（メニューの「メモ」の内容）があります。この項目がない既存データ・バックアップもそのまま読み込めます。

IndexedDBは `hibi-timeline-v2`（PWA版などWebサーバー経由。ローカルHTMLでは `hibi-timeline-v2:file:<pathname>`）、localStorageも同じ新しい名前空間を使用します。旧 `hibi-schedule` 領域は読み書きも削除もしません。

全編集は最新の不変スナップショットへ反映し、保存を直列化します。テキスト入力は500msのデバウンスとフォーカス移動・画面遷移時の保存を併用します。離脱時は未保存スナップショットを新名前空間のlocalStorageへ同期退避し、次回起動時に保存前の状態と一致する場合のみ回復します。

インポートは構造・バージョン・日付・時刻・ID・重複絶対時刻・候補参照を検証してから置換します。IndexedDBでは旧スナップショットと新データを一括トランザクションで書き、読み直し検証が済むまで回復情報を保持します。localStorageでは単一キーへの原子的な更新と回復情報を併用します。途中で中断した場合は次回の読み込み時に元の内容を回復します。

## ローカルHTMLの制約

端末・ブラウザー・開く方法によって `file://` やAndroidの `content://` での保存領域やファイルダウンロードの扱いは異なります。IndexedDBを優先し、使用できない場合はlocalStorageを試します。どちらも使えない場合は保存不可を画面に表示し、そのセッションのデータをエクスポートできます。保存容量不足などもエラーとして表示します。

HTMLの名前や保存場所を変えると、別の保存領域になる場合があります。更新前にエクスポートし、新HTMLでインポートしてください。端末のブラウザーデータ消去やプライベートモードによる消失、OSの強制終了で離脱イベントが発生しない場合の未保存入力は保証できません。

自動検証はPCのChromiumとスマートフォン相当の画面・タッチ設定で行います。Androidのcontentプロバイダー経由、iPhoneのローカルファイル閲覧環境は実機で確認が必要です。PWA版のインストールとオフライン起動は、Androidの実機（Chrome）でも確認してください。APKは実装していません。
